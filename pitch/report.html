สรุป — ผู้โดยสารรู้จากแอปอื่นว่ารถอยู่ไหน แต่ไม่รู้ว่าคันนี้ควรขึ้นไหม เราทำเว็บที่กรอกเลขข้างรถ (เช่น 7-3077) แล้วเห็นรุ่น เขต อู่ ค่าโดยสาร และคะแนนจากผู้โดยสาร 3 ด้าน (การขับ · การจอดป้าย · สภาพรถ) ผู้ใช้ได้แต้มจากรีวิวที่มีประโยชน์ และนำแต้มไปแลกสติกเกอร์/รูปโปรไฟล์ได้ รีวิวที่ผิดกติกาถูก report และผู้ดูแลซ่อนพร้อมหักแต้มได้ เข้าสู่ระบบด้วยบัญชี Google จริง ระบบรันจริงบน ruk-com (Nginx · Node.js 22 · PostgreSQL 16) มี test อัตโนมัติ 13 ชุด และ backup รายวันที่ทดสอบกู้คืนแล้ว

1ปัญหาและลูกค้า

ปัญหา

  • ViaBus / แอป ขสมก. บอกตำแหน่งและสาย แต่ไม่บอกว่าคันนั้นแอร์หรือพัดลม รุ่นอะไร ค่าโดยสารเท่าไร
  • ไม่มีช่องทางให้คะแนนคุณภาพการขับ: ขับหวาดเสียว ไม่จอดป้าย จอดกลางถนน
  • ร้องเรียน 1348 ได้ แต่ผู้โดยสารคนอื่นไม่เห็นผล ต่างจาก Grab / LINE MAN ที่ให้ดาวได้ทุกเที่ยว

ลูกค้า

  • ผู้โดยสารประจำ (กลุ่มหลัก) — นักเรียน นักศึกษา คนทำงาน ที่ขึ้นสายเดิมทุกวัน
  • ผู้ประกอบการเดินรถ (Phase 2) — feedback รายคันใช้ประเมินคนขับ
  • หน่วยงานกำกับ (อนาคต) — ข้อมูลรวมด้านความปลอดภัยแยกสาย/เขต/อู่

กันโกง (server ตรวจเอง ไม่พึ่งหน้าเว็บ)

  • ทุกการเปลี่ยนแต้มเป็น 1 แถวใน points_ledger · ยอด = SUM(delta) · ตรวจย้อนหลังได้
  • รีวิว + แต้ม อยู่ใน transaction เดียว · 1 รีวิว/คัน/วัน ด้วย partial unique index
  • โหวต/report/ของที่แลก ซ้ำไม่ได้ด้วย primary key / unique
  • แลกของล็อกแถวผู้ใช้ (FOR UPDATE) — กดพร้อมกันได้ของชิ้นเดียว แต้มไม่ติดลบ
  • สติกเกอร์ไม่ให้แต้ม · ต้องแลกก่อนใช้
  • รีวิว "คัน" ไม่ใช่ "คน": ห้ามชื่อ/รูปคนขับ · กรองคำหยาบ · ห้ามเบอร์โทร · ไม่รับรูป

4สถาปัตยกรรม

ที่ deploy จริง

  • ruk-com: TLS จบที่ load balancer · เครื่องไม่มี public IP · เข้าได้ทาง LB (เว็บ) และ SSH gate (key) เท่านั้น
  • Web: Nginx เสิร์ฟหน้าเว็บ + reverse proxy /api · rate limit 10 req/s (เข้าสู่ระบบ 10/นาที) · CSP
  • App: Node.js 22 + Express รันเป็น user busapi ผ่าน systemd · ฟัง 127.0.0.1
  • Data: PostgreSQL 16 ผ่าน unix socket แบบ peer auth (ไม่มีรหัสผ่าน DB) · ฟัง 127.0.0.1
  • Deploy คำสั่งเดียว ./deploy/deploy.sh (rsync + npm ci + migrate + restart)

ต่างจากแบบใน Sprint 0

  • แบบ: AWS VPC 2 subnet · จริง: ruk-com ไม่มี VPC → แยก tier ด้วย bind 127.0.0.1 และเตรียมสคริปต์ย้าย API + DB ไป node ที่ 2 (private IP + iptables + ALLOW_FROM) — ยังไม่ได้เพิ่ม node
  • Docker Compose → systemd · Let's Encrypt → TLS ที่ LB
  • รหัสผ่าน + bcrypt → เข้าด้วย Google เท่านั้น (ไม่มีรหัสผ่านในระบบ) · มีบัญชีทดสอบ @example.com เปิดคู่ไว้สำหรับเดโม

10ข้อจำกัดและงานต่อ

ข้อจำกัด

  • ยังเปิดบัญชีทดสอบคู่กับ Google จริง (ปิดได้ด้วย MOCK_LOGIN=0)
  • ยังเครื่องเดียว · backup อยู่เครื่องเดียวกับ DB ถ้าไม่ได้ดึงออก
  • word filter เป็นรายการคำ คำใหม่หลุดได้ — พึ่ง report
  • ยังไม่แจ้งผู้เขียนเมื่อรีวิวถูกซ่อน · ไม่มีอุทธรณ์
  • ค่าแต้มเป็นค่าที่ทีมตั้งเอง ยังไม่ได้ปรับจากข้อมูลจริง
