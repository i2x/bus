# ลูกขุนสุ่ม (ทีมล่าแม่มด) แทนผู้ดูแล

วันที่ 9 ต.ค. 2569

## ปัญหา

ตอนนี้รีวิวที่ถูกรายงานครบ 3 คนจะถูกซ่อน แล้วรอผู้ดูแล (ทีมเรา) ตัดสิน ถ้าผู้ใช้เยอะขึ้น ทีมอ่านไม่ไหว และคนนอกไม่รู้ว่าตัดสินกันยังไง

## แนวทาง

ให้ผู้ใช้ที่ถูกสุ่มเป็นลูกขุนตัดสินแทน แล้วประกาศคำพิพากษาให้ทุกคนดู ทีมเราไม่ตัดสินคดีอีก

## ขั้นตอน

1. รีวิวถูกรายงานครบ 3 คน: ซ่อนรีวิว (เหมือนเดิม) แล้วเปิดคดีรอบ 1
2. สุ่มลูกขุน 5 คน ส่งการ์ดในเว็บและข้อความ LINE (ถ้าผูกไว้)
3. ลูกขุนโหวต 🔥 เผา (ผิดกติกา) หรือ 🕊️ ปล่อย (ไม่ผิด) แบบลับ
4. ฝั่งไหนได้ 3 เสียงก่อน ปิดคดีทันที
5. ครบ 24 ชั่วโมงแล้วยังไม่มีฝั่งไหนได้ 3 เสียง: เปิดรอบ 2 กับลูกขุนชุดใหม่
6. รอบ 2 ยังไม่ได้ผล: แสดงรีวิวกลับ ไม่หักแต้ม (พิสูจน์ไม่ได้ถือว่าไม่ผิด)
7. ปิดคดีแล้ว ประกาศคำพิพากษา

## ใครเป็นลูกขุนได้

- สุ่มใน DB ด้วย `ORDER BY random()`
- ไม่ใช่คนเขียนรีวิว ไม่ใช่คนที่รายงานรีวิวนี้ และไม่เคยเป็นลูกขุนคดีนี้ในรอบก่อน
- บัญชีอายุอย่างน้อย `JURY_MIN_AGE_DAYS` วัน (ค่าเริ่ม 7) และมีรีวิวที่แสดงอยู่อย่างน้อย 1 อัน กันการสมัครหลายบัญชีมารอถูกสุ่ม ตอนเดโมตั้งเป็น 0
- มีคดีค้างไม่เกิน 3 คดี
- คนมีสิทธิ์ไม่ถึง 3 คน: คดีรอ แล้วลองสุ่มใหม่ทุกชั่วโมง ระหว่างนี้รีวิวยังถูกซ่อน
- ได้คนมีสิทธิ์ 3 หรือ 4 คน: เปิดคดีด้วยจำนวนนั้น ยังตัดสินที่ 3 เสียง

## โหวต

- ลูกขุนเห็นข้อความรีวิว เลขรถ เหตุผลที่ถูกรายงาน ไม่เห็นว่าใครรายงาน และไม่เห็นเสียงคนอื่นจนกว่าจะปิดคดี
- โหวตได้ครั้งเดียว เปลี่ยนไม่ได้
- โหวตได้ 2 ที่: การ์ดในแท็บ "ฉัน" หรือปุ่มในแชต LINE (postback `jury:<caseId>:hide|keep`) ทั้งคู่เรียกฟังก์ชันเดียวกัน

## ผล

| ผล | รีวิว | ผู้เขียน | รายงาน |
|---|---|---|---|
| เผา | ซ่อนถาวร | −20 (ครั้งเดียวต่อรีวิว เหมือนเดิม) | upheld |
| ปล่อย | แสดงกลับ | ไม่หัก | dismissed |
| รอบ 2 ไม่ได้ผล | แสดงกลับ | ไม่หัก | dismissed |

ลูกขุนที่โหวตตรงกับผล +3 แต้ม (`jury_majority`) รวมไม่เกิน 15 ต่อวัน กรณีรอบ 2 ไม่ได้ผล ไม่มีใครได้แต้ม

## คำพิพากษา (เปิดเผย)

- แสดงในหน้ารถคันนั้น และในตัวกรอง "คำพิพากษา" ของ feed
- โชว์ เลขรถ, ข้อความรีวิว, เหตุผลที่ถูกรายงาน (นับรวม เช่น หยาบคาย ×3), ผล, คะแนน เช่น 3–1, และลูกขุนทั้งหมดที่ถูกสุ่มในรอบที่ตัดสิน (รูปโปรไฟล์ + ชื่อ) ในชื่อ "ทีมล่าแม่มด"
- ไม่โชว์ ว่าใครโหวตอะไร, ชื่อคนรายงาน
- ผลเป็นเผา และมีรายงานเหตุผล "ข้อมูลส่วนตัว": ไม่แสดงข้อความรีวิว เขียนว่า "ข้อความถูกปิดเพราะมีข้อมูลส่วนตัว"
- ลูกขุนได้ LINE แจ้งผลและแต้มที่ได้

## ผู้ดูแล

เอาคิวผู้ดูแลออกจากเว็บ เอา `/api/mod/*` ออก คอลัมน์ `role` ใน `users` คงไว้ไม่ใช้ (ไม่ต้อง migrate)

## ข้อมูล

```sql
jury_cases (
  id serial PK, review_id int → reviews, round smallint (1|2),
  status text: 'waiting' | 'open' | 'hide' | 'keep' | 'no_verdict',
  deadline timestamptz, created_at, closed_at
)
jury_seats (
  case_id int → jury_cases, user_id int → users,
  vote text NULL ('hide' | 'keep'), voted_at,
  PK (case_id, user_id)
)
```

- รอบ 2 เป็นแถวใหม่ใน `jury_cases` ของรีวิวเดียวกัน
- สุ่มและปิดคดีใน transaction เดียว ล็อกแถวคดีด้วย `FOR UPDATE` กันโหวตพร้อมกันแล้วปิดซ้ำ

## API

| | |
|---|---|
| `GET /api/jury` | คดีที่ฉันเป็นลูกขุนและยังไม่ได้โหวต |
| `POST /api/jury/:caseId/vote` `{vote}` | 403 ถ้าไม่ใช่ลูกขุน · 409 ถ้าโหวตแล้วหรือคดีปิดแล้ว |
| `GET /api/verdicts?fleet=` | คำพิพากษาล่าสุด 30 คดี (ไม่ต้องเข้าสู่ระบบ) |

ตัวจับเวลาใน API ทุก 5 นาที: ปิดคดีที่หมดเวลา (เปิดรอบ 2 หรือ no_verdict) และลองสุ่มคดี waiting ที่รอครบชั่วโมง

## Test (แทน test moderator เดิม)

- คนเขียนและคนรายงานไม่ถูกสุ่ม
- คนที่ไม่ใช่ลูกขุนโหวตได้ 403 · โหวตซ้ำได้ 409
- ก่อนปิดคดี `GET /api/verdicts` ไม่มีคดีนี้ และ `GET /api/jury` ไม่บอกเสียงคนอื่น
- 3 เสียงเผา: ซ่อน, ผู้เขียน −20, ลูกขุนฝั่งชนะ +3
- หมดเวลาแบบเสมอ: รอบ 2 ลูกขุนไม่ซ้ำรอบ 1 · รอบ 2 หมดเวลา: รีวิวแสดงกลับ
- คำพิพากษาไม่มีฟิลด์ที่ผูกลูกขุนกับเสียง · คดีข้อมูลส่วนตัวไม่มีข้อความรีวิว

(ใน test ปรับเวลาโดยแก้ `deadline` ใน DB ตรง ๆ แล้วเรียกตัวจับเวลา)
